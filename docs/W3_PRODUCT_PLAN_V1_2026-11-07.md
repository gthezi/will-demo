# Will W3 产品规划与交互设计 V1.0

- 版本：V1.0
- 整理日期：2026-11-07
- 状态：产品讨论基线，待用户审阅
- 适用对象：产品讨论、前端设计与后续 Codex 实施规划
- 前置版本：W1 工作台与项目管理、W2 AI 工作区

> 本文确定 W3 的产品目标、主要页面、交互关系和实施边界。它不是代码实现任务书，也不代表已经授权启动开发。用户审阅并确认后，再据此创建 W3 执行 Issue。

## 1. 阶段目标

W1 建立了项目、任务、日历和工作台；W2 建立了独立 AI 工作区、历史会话、可恢复草案，以及人工确认后写入正式任务的流程。

W3 将资料管理接入这套工作流，让用户能够：

1. 把通知、要求、笔记和网页等信息保存为资料；
2. 在全局资料库或具体项目中找到同一份资料；
3. 把资料交给现有 AI 工作区整理，并查看回答依据；
4. 将整理结果转成可编辑的任务草案，经人工确认后进入项目；
5. 从任务或 AI 回答返回对应的原始资料。

W3 的主要交付是**资料管理、资料与项目的关联、AI 资料工作流，以及 AI 服务设置界面**。

## 2. 产品决策

以下内容作为 V1.0 的规划基线，待用户审阅。

| 主题 | W3 规划决定 |
|---|---|
| 主导航 | 新增「资料库」入口；保留「项目」和「AI 工作区」独立入口 |
| 项目资料 | 项目详情继续保留「资料」标签，显示与该项目关联的资料 |
| 资料类型 | 首版支持文本资料和外部链接 |
| 资料关系 | 一份资料可以关联多个项目；项目内显示的是同一份资料，不复制内容 |
| 资料编辑 | 原始内容可查看和编辑；AI 摘要不覆盖原文 |
| AI 入口 | 复用 W2 的会话、历史、草案审阅和确认流程 |
| AI 上下文 | 从资料进入 AI 时，明确携带资料 ID 和可用的项目 ID |
| 来源追溯 | AI 回答、搜索结果和生成任务保留来源引用 |
| 内部检索 | 首版实现本地关键词检索，不引入向量数据库 |
| 外部搜索 | 提供搜索结果的交互演示；当前仍是 Mock，不执行真实联网搜索 |
| 模型服务 | 提供团队默认服务、个人服务的设置界面；不接入真实模型 |
| 数据保存 | 资料使用独立版本化本地存储，与 W1 安排数据分开 |
| 删除策略 | 首版以归档和解除关联为主，不因解除项目关联而删除资料 |

## 3. 信息架构

### 3.1 主导航

建议主导航顺序：

1. 今天
2. 日历
3. 项目
4. 资料库（W3 新增）
5. AI 工作区
6. 设置

各入口职责：

- **今天**：查看当前任务和近期安排。
- **日历**：按日期查看日程和截止事项。
- **项目**：管理项目、任务及项目内资料。
- **资料库**：跨项目管理所有资料。
- **AI 工作区**：管理会话、整理资料、搜索外部信息和生成任务草案。
- **设置**：管理个人偏好和 AI 服务选项。

### 3.2 项目详情

项目详情保留基础标签：

- 概览
- 任务
- 资料

资料标签显示关联到当前项目的资料。它与全局资料库使用同一套资料记录和数据状态。

项目概览可以增加资料数量和最近更新资料的摘要，但不在概览中重复展示完整资料列表。

## 4. 资料库页面

### 4.1 页面布局

桌面端采用双栏结构：

- 左侧：资料列表、搜索、类型筛选和排序；
- 右侧：当前选中资料的详情和操作。

选择资料时在右侧更新详情，避免频繁跳转。

窄屏改为列表页和详情页之间的导航，不强行维持双栏。

### 4.2 资料列表

每条资料至少显示：

- 标题；
- 类型（文本 / 链接）；
- 一段内容摘要或备注；
- 所属项目；
- 最近更新时间。

支持的筛选和排序：

- 全部资料、最近更新；
- 文本资料、链接资料；
- 按项目筛选；
- 按标签筛选；
- 最近更新、创建时间、标题排序。

默认列表不展示已归档资料；提供查看归档资料的入口。

### 4.3 资料详情

文本资料显示标题、正文、标签、关联项目、创建和更新时间。用户可以编辑标题、正文和标签。

链接资料显示标题、URL、备注、域名或来源信息，以及打开原网页的操作。首版不自动抓取网页全文；用户可以手动补充正文或备注。

详情页提供：

- 编辑资料；
- 关联项目 / 解除项目关联；
- 归档 / 恢复；
- 交给 AI 整理；
- 查看相关 AI 会话（如果存在关联）。

### 4.4 新建资料

提供三个入口：

1. 新建文本资料；
2. 添加外部链接；
3. 载入示例资料。

在项目资料标签中创建资料时，自动关联当前项目。全局资料库创建时默认不关联项目，用户可以稍后添加关联。

文本编辑器首版以标题和正文为主，不引入复杂富文本排版、附件嵌入或协同编辑。

## 5. 项目资料关联

### 5.1 关联已有资料

在项目资料标签点击「关联已有资料」，打开资料选择器。用户可以搜索并选择一份或多份已有资料。

关联操作只增加项目与资料之间的关系，不复制资料正文。

### 5.2 新建并关联

从项目资料标签创建资料时，创建完成后自动关联当前项目。

### 5.3 解除关联和归档

- 解除关联只移除当前项目与资料之间的关系，资料仍保留在全局资料库。
- 归档资料会使其默认退出常规列表，但历史会话和任务中的来源引用仍可查看。
- 项目归档不删除该项目的资料关联。
- 首版不提供无提示的永久删除操作。

## 6. AI 资料工作流

### 6.1 从资料进入 AI

资料详情提供「交给 AI 整理」入口。

进入 AI 工作区时：

- 创建新会话，或按明确的交互规则继续当前会话；
- 自动带入当前资料 ID；
- 如果资料关联了当前项目，则带入项目 ID；
- 在对话区域明确显示当前参考资料；
- 用户可以查看或移除上下文中的资料。

不能仅凭资料当前所在的页面推断 AI 已经读取了资料。界面必须明确显示实际加入上下文的资料。

### 6.2 对话中的资料引用

AI 回答可以展示引用资料卡片，至少包含资料标题和引用片段。

点击引用应打开原始资料详情。若资料已归档，仍允许通过历史引用查看；若资料不可用，应明确提示，不得静默替换为其他资料。

资料原文与 AI 回答分开保存。重新整理、修改提示或切换会话都不能覆盖原始资料。

### 6.3 整理结果与任务草案

AI 可以将资料内容整理成摘要、要求清单或待办建议。

需要转成任务时，继续使用 W2 已有的草案审阅流程：

1. 展示生成的任务草案；
2. 用户检查标题、项目、截止日期和其他字段；
3. 用户可以编辑或移除单项；
4. 用户点击确认后才写入正式任务；
5. 正式任务保留 AI 会话和来源资料的关联。

不能因为 AI 提取出一条要求，就自动创建正式任务或修改已有任务。

### 6.4 AI 快捷操作

W2 已有「整理通知」和「拆解任务」。W3 增加：

- **整理资料**：提炼主要内容、关键要求和待确认信息；
- **提取任务**：从资料中提出待办建议，进入现有草案审阅流程；
- **搜索外部信息**：在 Mock 场景中展示搜索结果和来源。

快捷操作使用同一套会话和消息流，不建立第二套资料专用聊天系统。

## 7. 外部搜索与结果保存

### 7.1 W3 的实现边界

当前前端没有真实模型服务和搜索后端。因此 W3 只实现外部搜索的交互流程和 Mock 示例数据，不声称已经执行真实联网搜索。

Mock 场景应明确标记，避免用户将演示结果误认为实时检索结果。

### 7.2 搜索结果

每条结果展示：

- 标题；
- 来源名称或域名；
- 摘要；
- 原网页地址；
- 保存到资料库的操作。

用户可以打开原网页，也可以将有价值的结果保存为链接资料，并选择关联项目。

保存后，结果成为正式资料；未保存的搜索结果只保留在对应会话中。

### 7.3 与资料库的关系

保存的外部结果采用链接资料类型。原始 URL 和来源信息应保留，AI 生成的摘要作为分析内容单独呈现，不替代来源页面。

## 8. 内部搜索

### 8.1 首版必须支持

资料库内本地关键词检索，覆盖：

- 资料标题；
- 文本正文；
- 链接备注；
- 标签；
- 关联项目名称。

支持按资料类型和项目筛选。搜索结果可以直接打开资料详情。

### 8.2 暂不实现

- 向量检索；
- 语义相似度搜索；
- 自动网页全文抓取；
- PDF / DOCX 全文索引；
- 跨设备索引和云端搜索。

如果实现成本允许，可以在资料库搜索结果中附带匹配的项目名称；不要求本轮新建一个覆盖所有页面的全局搜索系统。

## 9. AI 服务设置

在现有设置页增加「AI 服务」区域。

### 9.1 服务来源选择

界面提供：

- 团队默认服务；
- 个人服务。

个人服务可以展示供应商预设、自定义兼容接口和模型名称等配置入口。当前阶段只做可操作的界面演示，不连接真实接口。

### 9.2 API Key 安全边界

W3 不收集、不发送、不持久化真实 API Key。不要把用户输入的密钥写入 localStorage、会话数据、日志或测试截图。

如果需要展示 API Key 配置位置，应使用明确标记为未启用的占位控件，不能让用户误以为输入后已经生效。

### 9.3 联网搜索偏好

提供「允许 AI 使用外部搜索」开关并保存本地偏好。

在 Mock 阶段，该开关只控制演示流程是否展示外部搜索结果，不代表真实网络权限或真实搜索能力。

## 10. 数据结构与持久化建议

本节是供实现阶段评估的数据模型建议，不要求照搬字段命名。

### 10.1 资料记录

建议的核心字段：

| 字段 | 含义 |
|---|---|
| id | 稳定资料 ID |
| type | text 或 link |
| title | 资料标题 |
| content | 文本正文，可选 |
| url | 链接地址，可选 |
| note | 备注，可选 |
| tags | 标签数组 |
| createdAt | 创建时间 |
| updatedAt | 更新时间 |
| archivedAt | 归档时间，可选 |

文本资料必须有正文或可编辑内容；链接资料必须有有效 URL。字段校验在领域层完成。

### 10.2 项目关联

单独维护资料与项目之间的关联，例如：

- materialId；
- projectId；
- linkedAt。

一份资料可以关联多个项目。解除关联只删除关系记录，不删除资料本身。

### 10.3 AI 上下文与来源

在不破坏 W2 现有会话和来源结构的前提下，增加可选关联：

- 会话可记录当前参考资料 ID；
- 消息可记录资料引用或外部搜索引用；
- AI 生成的任务继续保留 W2 的 conversationId、batchId、messageId 和原始输入来源；
- 在此基础上增加可选的 material ID 引用。

不要用新的资料来源字段替换 W2 已有的任务来源信息。历史 W1/W2 数据必须能够继续读取。

### 10.4 独立存储

资料库使用独立的版本化本地存储键，例如 `will-material-library-v01`，不直接改写 W1 的 ScheduleData，也不将资料正文塞入 AI 会话副本。

持久化应具备：

- 格式和字段校验；
- 读取损坏时保留原始内容并给出提示；
- 写入失败时明确提示当前修改仅在本次页面有效；
- 刷新和 Electron 重启后的恢复；
- 对旧数据结构保持向前兼容，不擅自删除旧存储。

资料和项目关联可以放在同一份资料库状态中，以保证创建、关联和保存的一致性。

## 11. 实施阶段

### W3-A：资料管理

交付：

- 主导航新增资料库；
- 全局资料列表和详情；
- 文本资料新建、编辑、归档和恢复；
- 外部链接新建、编辑和打开；
- 本地关键词搜索、类型和项目筛选；
- 项目资料标签；
- 关联已有资料、创建并关联、解除关联；
- 独立本地持久化及异常处理。

验收重点：同一资料在全局资料库和多个项目中保持一致；刷新或重启后数据与关联仍然存在。

### W3-B：AI 资料工作流

交付：

- 从资料详情进入 AI；
- 会话上下文关联资料和项目；
- 对话中展示当前参考资料；
- Mock 资料整理和任务提取；
- 回答中的资料引用及返回原文；
- 任务草案沿用 W2 审阅、编辑和人工确认；
- Mock 外部搜索结果、打开来源和保存为链接资料。

验收重点：资料、会话、回答、任务之间的来源关系可追溯；AI 不会跳过人工确认修改正式安排。

### W3-C：AI 服务设置与整体验收

交付：

- 团队默认 / 个人服务模式选择；
- 供应商、接口和模型配置界面；
- 明确未启用的 API Key 占位控件；
- 联网搜索偏好；
- 日间 / 夜间主题和窄屏适配；
- W1、W2 回归测试和 Electron 重启测试。

验收重点：设置状态可以按约定保存；任何 Mock 设置都不会被描述为真实模型或网络能力。

## 12. 端到端验收场景

以「课程论文」项目为例：

1. 在资料库中新建一份论文要求文本，并添加一条参考网页链接。
2. 将两份资料关联到课程论文项目。
3. 在项目资料标签和全局资料库中均能找到它们。
4. 打开论文要求，交给 AI 整理；AI 工作区明确显示参考资料和项目。
5. AI 生成摘要和任务建议，回答能够引用原始资料。
6. 用户将任务建议转成草案，修改标题或截止日期，再人工确认。
7. 项目任务看板中出现新任务；任务保留来源会话和资料 ID。
8. 从任务或 AI 回答返回原始资料。
9. 将参考资料解除课程论文关联，确认它仍在全局资料库和其他关联项目中。
10. 关闭并重启 Electron，资料、关联、会话、草案状态和已确认任务均正确恢复。

此外至少覆盖：

- 空资料库和大量资料；
- 长标题、长正文、无备注链接和异常 URL；
- 重名资料；
- 同一资料关联多个项目；
- 归档资料与归档项目；
- 存储不可用、坏数据和写入失败；
- AI 取消、草案编辑、移除、确认失败和重复确认；
- 资料已归档时的历史引用；
- 日间 / 夜间主题；
- 桌面常用尺寸与窄屏布局；
- W1/W2 原有浏览器和 Electron 回归。

## 13. 暂不纳入 W3

以下能力不作为 W3 验收条件：

- PDF、DOCX、PPTX 等文件上传和解析；
- OCR、图片文字提取；
- 自动抓取任意网页正文；
- 真实 LLM API 调用；
- 真实联网搜索服务；
- 向量数据库、Embedding 和复杂 RAG；
- 账号系统、云端同步和多人协作；
- 多窗口并发编辑与冲突合并；
- Agent 自动执行任务、自动修改正式安排；
- 系统通知和第三方服务集成。

这些方向可以在资料库和 AI 工作流稳定后，根据实际使用需求再安排。

## 14. 待用户审阅的问题

以下问题不妨碍形成 V1.0 产品基线，但在创建执行 Issue 前应确认：

1. **资料标签**：首版是否采用用户自由输入标签，还是提供少量预设分类？
2. **资料与项目关系**：是否确认一份资料可以关联多个项目？本规划按多对多设计。
3. **跨对象搜索**：W3 是否只要求资料库搜索，还是希望同时搜索任务、日程和项目？当前基线只把资料搜索列为必须。
4. **资料归档**：是否接受首版只提供归档 / 恢复，不提供永久删除？
5. **个人 API 配置**：是否只展示未启用的配置界面，等后端安全存储方案明确后再开放真实 Key 输入？
6. **外部搜索演示**：是否接受使用固定 Mock 结果演示「搜索—查看来源—保存到资料库」的完整交互？
