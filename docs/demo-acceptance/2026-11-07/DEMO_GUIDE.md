# Will PC 校园展示指南

## 打开客户端

将 `WillPC-0.1.0-windows-x64.zip` 完整解压，打开其中的 `WillPC-win32-x64/WillPC.exe`。不用启动服务端。第一次是空白安排，可以点击左侧“示例”，确认载入。

展示前先说明：**当前 AI 是本地规则模拟，展示的是安排识别、编辑确认和页面联动；不是已接入真实大模型。提醒只保存偏好，不会弹出通知。**

## 建议演示顺序

1. 在“项目”中新建“校园课程展示”。
2. 点击“AI 助手”，输入：**明天下午三点有校园讲座，五点前提交课程报告**。
3. 生成草案后先展示两项摘要。展开“编辑”，将标题改为“校园人工智能讲座”“提交人工智能课程报告”，关联到新建项目；讲座可改为 90 分钟。
4. 点击“确认添加 2 项”，再点“查看日历”，检查明日的讲座和报告。
5. 勾选报告为完成，再到项目页恢复。回到首页查看待办、截止列表与项目。
6. 切换日夜主题。完全退出后重新打开，说明确认过的安排和设置仍在。
7. 用“整理课程资料”展示模糊输入：缺少日期和时间时需要人工补全，不能直接确认。取消不会添加安排。

截图中使用了固定的 11 月 7 日测试时间；实际演示的“明天”和示例日期会随电脑当前时间变化。

## 展示前检查

- 先在演示电脑实际打开一次。此包尚未签名，另一台电脑可能有系统信誉或安全软件提示；本次仅在开发电脑完成运行验收。
- 1366×768 或更大的窗口适合双栏演示，较小窗口可以纵向滚动。
- 使用专门的演示数据。载入示例会替换当前安排与项目，确认对话框会提示。
- 已保存安排不依赖网络；如果现场服务端不可用，本展示不受影响。

## 保存、备份与恢复

正式客户端把数据保存在本机 `%APPDATA%\WillPC`。它与浏览器里的试用数据、开发预览数据各自独立。

需要备份时，先通过“文件 → 退出”完全关闭客户端，再复制整个 `WillPC` 数据目录到单独的备份文件夹。不要只复制程序 EXE，也不要在程序打开时复制正在写入的数据库。

需要从备份恢复时，先退出客户端，将现有 `WillPC` 目录改名保留，然后把完整备份复制回 `%APPDATA%\WillPC`，再启动程序。本轮实测了关闭后复制备份、恢复到另一独立数据目录并重启；没有验证跨电脑迁移。

如果页面提示“无法读取本地安排”，当前操作只能暂存在内存里。原始损坏值会被保留，便于恢复。此时可临时载入示例继续展示，但这些临时操作不会在退出后保留；不要把它当作数据已修复。

## 开发与重新打包

Windows 上准备 Node 22.12 或更新版本，在仓库的 `will-app` 目录中执行：

```powershell
npm ci
npm run desktop:dev
```

默认开发服务为 `http://127.0.0.1:5177/`。关闭桌面窗口会同时停止本次开发服务；端口已被占用时会直接报错，可以用 `WILL_DEV_PORT` 指定另一个固定端口。

生产构建并打包：

```powershell
npm run desktop:package
```

每次输出到独立的 `out/windows/<版本-时间>/`，不会覆盖旧包。最新结果记录在 `out/windows/latest.json`。

单独检查生产资源启动：

```powershell
npm run desktop:build
npm run desktop:start
```

开发预览使用 HTTP 地址，生产包使用固定的 `will://app/` 地址，所以两者不会自动共享同一份安排。正式客户端不需要本地 HTTP 服务。

验收脚本为 `tests/desktop.browser.cjs` 和 `tests/desktop-dev.browser.cjs`；通过 `WILL_PLAYWRIGHT_MODULE` 指向已有 Playwright 安装。前者默认检查源码生产模式，设置 `WILL_DESKTOP_EXE` 后检查实际打包程序；全部使用临时数据目录。
