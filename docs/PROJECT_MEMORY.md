## 1. 一句话介绍与当前目标

Will 是面向校园学习与活动场景的个人安排助手：用户输入安排或通知内容，系统提供可核对、可编辑的日程 / 待办草案；用户确认后，安排在日历、待办和项目中同步呈现，可修改、完成和恢复。

**当前工作阶段**：2026-11-07（周六）汇报的 Windows PC 可交互展示原型已形成可运行候选版；正在做最终现场展示准备与交接整理。不要将“原型已完成”理解成正式产品、完整服务端或真实大模型能力已经上线。

## 2. 项目与团队背景

- 团队由校园同学组成，分产品、技术、展示等职能；此前用户负责技术组的一版 Windows 客户端设计和实现协调。
- 前期开展 58 份大学生信息整理与日程管理问卷，结果供需求讨论：回答首要困扰的 55 人中，35 人选信息查找 / 汇总，12 人选事项或截止日期遗忘；不同痛点的实际后果强度并不一致。问卷只能支持问题排序与进一步验证方向，不能直接证明某个 MVP 已被验证。
- 2026-11-03 技术会议提出首页总览 / 今日截止 / 待办看板 / 个性化设置，核心展示流程为“输入 → 识别排期 → 用户操作 → 日历 / 待办显示”。最初建议 Qt Windows，三名开发者各自尝试一版 Windows 前端（“赛马”）；**不是三个操作系统同时开发**。
- 随后用户独立选择 React + TypeScript + Vite，并通过 Electron 做 Windows 封装，以减少原型到桌面客户端的重写。该选型为当前**这版原型的实际实现路线**，不应直接表述为整个团队已永久统一技术栈。
- Frank 负责服务端方向；会议曾讨论 JSON 通讯、Token 鉴权、Session ID 和日程同步。**这些是当时的服务端规划，不代表本仓库已实现，也不是已验收的 API 契约**。
- 旧的 Qt / 多端和服务端复杂协议草案是历史决策背景。后续以团队最新确认、服务端实际接口和代码为准。

## 3. 当前客户端状态（2026-11-06）

**技术栈**：React + TypeScript + Vite + Ant Design + Dayjs；Windows 包装使用 Electron。代码入口 `will-app/`。

当前可操作：
- 深浅主题、窄导航与双栏工作台，首页展示近期截止、今天尚未过期的待办、全部待办完成进度、紧凑月历、项目概览。
- 日程与待办的新增、编辑、删除；日期 / 时间字段校验，待办完成 / 恢复；项目新建、改名、归档与恢复。
- 设置页选择“近期”范围 3 / 7 / 14 / 30 天（本地自然日，含今天）；首页统计与列表共用规则，逾期另列；统一状态颜色和到秒的逾期判断。
- AI 助手文本输入 → **本地规则模拟**识别 → 多条草案预览、展开编辑、校验和人工确认 → 日历 / 待办 / 项目联动。
- 首页全日期安排搜索与组合筛选；数据与偏好本地持久化，部分兼容历史数据；保存失败或坏数据时有提示。
- Electron Windows x64 免安装 ZIP，完整解压后启动 `WillPC.exe`；生产资源由 `will://app/` 本地加载，不需要 Vite 服务或联网服务端。

**尚未实现或仅为演示行为**：
- 没有真实 LLM / 云端 AI 请求、服务端账户、跨设备同步；AI 草案使用规则模拟，遇到复杂文本必须人工校验。
- “提前提醒”目前只保存偏好，**没有系统通知 / 到点提醒**。
- 尚无正式签名、安装器或自动更新；另一台 Windows 机器上的首次启动 / SmartScreen 等仍需独立验证。
- Electron 客户端、本地开发预览和网页测试版的数据彼此独立，不会自动同步。
- 未确认的草案在关闭 / 重启后不保证保留；桌面用户数据存于 `%APPDATA%\WillPC`。

- 已新增 [下一版 PC 信息架构与交互构想（团队讨论稿 V0）](product/WILL_PC_INFORMATION_ARCHITECTURE_DISCUSSION_V0_2026-11-06.md)，用于与产品组、技术组讨论功能区域、页面关系、实际交互、设计取舍及开发优先级。
- 已新增 [下一版 PC 前端产品与实施规划 V0.2（讨论稿）](product/WILL_PC_FRONTEND_IMPLEMENTATION_PLAN_V0_2_2026-11-06.md)：细化页面职责、可选截止时间的任务模型、统一数据来源、Mock 交互、W0–W4 工作包与验收要求。**待用户和团队讨论确认，尚未授权 Codex 实施。**
- 用户个人倾向采用**方案 A：以工作对象组织**：暂建议“今天、项目、资料库、日历、AI 工作区”五个主要工作入口，搜索 / 提醒 / 设置作为全局能力；论文、流程、协作优先考虑项目内专门视图。
- **用户已确认的产品原则（2026-11-06）**：普通任务可不设置截止日期或时刻；只设截止日期也有效，日历事件需要明确日期与开始时间。无截止日期的任务继续存在于项目看板与任务列表，不强制进入日历；日期截止任务不虚构具体截止时刻。新任务模型需要与 Windows 展示版的历史数据兼容。此决定仅确认产品语义，不代表授权编码或团队最终批准整体方案。
- **用户已确认的项目页面原则（2026-11-06）**：所有项目默认采用“概览 / 任务 / 资料”三个基础视图；“论文 / 流程 / 协作”作为按项目类型或需要启用的专用视图。共用任务、日程和资料数据，避免各视图重复存储。页面具体布局、模板规则及团队最终选择仍待讨论，也未授权开始编码。
- **用户认可的项目创建方式（2026-11-06）**：采用“预设模板 + 自由调整”。普通项目、课程论文、流程申请、小组协作等作为初始配置选择；所有项目保留三个基础视图，可在创建后自由启用、隐藏和重新启用论文 / 流程 / 协作等专用视图。隐藏视图不得删除已有业务数据。模板名称与初始组合仍供团队商议，尚未授权开发。
- **用户认可的 AI 交互方向（2026-11-06）**：独立 AI 工作区采用**自由对话 + 快捷功能入口**；快捷功能帮助用户发起整理通知、任务拆解、资料整理、安排调整等请求，仍沿用同一套对话、上下文和结构化草案确认流程。具体页面细化和 W2 Mock 验收范围已补充到 [前端规划 V0.2](product/WILL_PC_FRONTEND_IMPLEMENTATION_PLAN_V0_2_2026-11-06.md)。快捷功能数量与具体布局属于提议，尚未授权编码。
- **状态仍为待讨论**：这是当前个人偏好和初步设计构想，不代表整个团队认可了最终导航 / 页面清单，也不授权 Codex 实施。本讨论记录不改变已验收 Windows 展示版本和已有 Draft PR 的合并状态。
