## 1. 本轮最新决定（优先于旧成本估算与设计建议）

1. **当前 Will 前端过分偏向日历管理**；下一阶段应以产品组《Will 项目计划书》（2026-11-05）对“面向大学生日常任务的 AI 工作台”的定位为主，重新梳理工作区功能组织和交互，而不只继续打磨日历页面。
2. **产品组 14 页 Figma PDF 主要是视觉与页面构成参考**。其中的 14 个画面不是要求全部照搬开发，也不能直接推导正式导航列表。**具体功能区、页面数量和层级需要回到计划书的场景、用户目标和已有实现一起分析**，之后再与用户讨论确认。
3. **当前 React 前端已有白天主题，整体色彩、卡片和留白已经与产品组浅色稿比较接近**。暂不开展“把深色 App 全面换成浅色”的大项目；可以保留深浅主题，通过布局和组件局部微调与视觉参考协调。
4. **当前阶段主要做 PC 前端的页面设计、导航、状态与交互，尽可能复用已有 React + TypeScript + Vite + Electron 源码**。复杂 AI 处理、资料解析、多人同步等能力主要由未来服务端/后端提供；前端可以使用明确标记的 Mock 和适配层模拟整个用户流程、留好可替换接口。**但前端仍须负责状态呈现、输入校验、人工确认、错误/加载/空状态、前端数据关联及安全地调用接口**，不能把这些也简单推给后端。
5. **先做好规划再交给 Codex 执行**。重新评估工作量时须区分“现有页面改布局、增加 Mock 页面及交互、对接真实后端”三种不同成本。先前依据 14 张视觉稿对完整真实功能开发的较高估算，**不适合作为此轮前端-only 规划的工作量结论**。
6. Will 是产品组/技术组共同协作项目，前端应尊重产品组的目标和设计贡献，避免自行认定当前技术组原型或者任何一版 Figma 为最终标准；必要的取舍通过具体页面与场景对照一起讨论。

## 3. 新对话推荐的讨论顺序（不预定结论）

### 第一步：从计划书的**用户任务和内容对象**出发分析产品

围绕课程论文 / 小组作业、校园通知转任务、资料整理、流程跟进、多人协调等场景，明确：
- 用户开始一件事时**从哪里进入**，能看到什么；完成一次操作后又到哪里找回来？
- 项目、任务、日程、文件、资料卡、流程步骤、AI 草案/对话、提醒、协作对象之间**哪些是数据对象，哪些只是同一对象的不同视图或入口**？
- 哪些操作必须实时生效，哪些需要等待服务端，哪些可以 Mock？场景之间需要怎样传递上下文？

不要因为视觉稿画了 14 张页面，就自动创建 14 个导航项；也不要因为当前代码只有四个页面，就默认新设计只能有四个页面。

### 第二步：对照 14 页视觉参考和现有运行版本，提出**信息架构候选**

至少分析“今天/首页、项目与待办、日历、AI 工作区、资料与论文/流程、协作、提醒、搜索/设置”之间的合理层级；允许将多个相邻功能合并为工作区内部视图。尽量沿用现有日间主题、Ant Design 组件与基础数据逻辑。

提交给用户讨论的是：
- 1–2 个有明确取舍理由的导航/页面组织方案；
- 每个主要区域的核心操作流程（含新增、编辑、确认、跳转、空状态/加载/失败）；
- **现有页面可改造、需要新增前端 Mock、依赖服务端后续实现**三类任务的映射；
- 和产品组视觉稿可复用的视觉细节及不适合照搬的设计；
- 桌面主窗口下信息密度与 AI 对话是独立页还是辅助面板的安排。

### 第三步：把**经过讨论确认的方案**拆成 Codex 可执行的前端工作包

推荐优先做新版框架、导航和典型页面的真实交互原型，用 Mock 驱动，然后逐步覆盖其他页面。每个工作包包含页面与状态清单、交互/跨页面事件、必要的 TypeScript 请求与响应类型、可替换接口、对照 Figma/现版截图的验收方式。服务端接口尚未正式提供时，示例数据与本地适配层只能作为**前端约定的建议**，不能宣称与 Frank 的服务端协议已达成一致。

**验证要求**：保留已完成的日程/项目数据、确认流程、localStorage 数据兼容和 Electron 启动；不破坏日夜主题。新入口如果尚不可用，明确“设计预览/模拟数据”，而非伪装已经联通服务端。

## 4. 当前不做的事

- **不**在此轮直接修改 React/Electron 代码或启动全面 UI 重构；
- **不**直接将 Figma 每张图照搬成独立页面或立即确立八个正式一级导航；
- **不**因为视觉稿为浅色而删除现有夜间主题；
- **不**把文件解析/协作/真正的 AI 等后端复杂功能实现工作量算入“纯前端页面改造”的成本，也**不**宣称这些功能已经接入；
- **不**合并 PR #1–4、改变 GitHub Pages 发布、影响 11 月 7 日已验收的展示包；
- **不**为仓库记忆再扩展大型治理结构。下一步以设计决策和可落地的产品成果为中心。

## 5. 建议在新对话开始时提交的首个成果

一份有图或简明页面结构说明的 **《Will 下一版 PC 前端信息架构与交互讨论稿 V0》**，至少回答：

1. Will 作为 AI 工作台，首页的职责如何变化，怎样避免继续只是日历工具？

3. 现有 React 代码能复用到什么程度，怎么迁移界面而不损失已验证功能？
4. 主要业务场景怎么跨工作区流动？AI 结果卡在哪儿编辑、确认、查回？
5. 前端 Mock/接口契约的最小边界在哪里？哪些要等后端团队确认？
6. 哪些页面先做、哪些后做，按什么验收；对“纯前端”改造成本给出分档而非混同完整产品开发。
