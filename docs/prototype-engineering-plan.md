# 原型工程化与试用安排

记录日期：2026-11-05

## 当前方向

用户反馈：试用者普遍认为 HTML 原型的布局和交互更友好。用户提出下一步以原型为依据完成工程化，并上线供他们试用。

视觉和操作参考以 `Will_PC_交互原型_V0_1.html` 为主。现有 React 工程提供可复用的数据、校验、持久化和业务流程。迁移时分别检查画面和行为，保留原型中受欢迎的布局、信息层级和入口位置。

原型布局和主要交互已迁入 React，当前在 `feat/prototype-experience` 分支维护。改造前版本固定为标签 `react-demo-before-prototype-2026-11-05`；入门教程的固定分支和标签保持不变。

## 本轮完成

- 恢复窄导航栏、紧凑顶部栏和右下角快速添加。
- 首页采用任务进度、近期截止、待办清单、月历与项目概览的组合布局；搜索图标展开全日期筛选。
- 日历提供月视图和所选日期的安排；项目页保留新建、改名、归档、恢复与按项目添加。
- 设置页提供显示名称、日夜及系统主题、载入示例和清空安排。
- 助手沿用输入、编辑草案、确认添加的流程，调整抽屉与草案的视觉呈现。
- 根据用户反馈，删除所有页面重复的介绍标题与说明、首页问候日期块以及顶部“手动添加”。页面名称仅保留在顶栏，相关添加入口继续可用。HTML 原型也同步移除了这些介绍块。

本轮恢复了原型的信息布局与操作入口，并非逐像素复制。首页使用真实任务进度替代装饰图形，助手继续采用可核对的草案表单。后续可根据试用反馈继续调整画面。

## 可行性

工作量判断为中等，主要集中在前端页面和交互迁移。

| 可以复用 | 需要按原型迁移或补齐 |
| --- | --- |
| React、TypeScript、Vite 工程与构建流程 | 窄导航栏、顶部操作和右下角快速添加 |
| 日夜及系统主题的状态与持久化 | 原型的配色、间距、页面比例与视觉层级 |
| 安排类型、校验、增删改和完成状态 | 首页的近期截止、待办清单、月历和项目概览组合 |
| 项目新建、改名、归档和恢复 | 日历、项目、设置页与原型一致的呈现和入口 |
| AI 草案识别、取消、编辑与确认保存 | 原型助手抽屉的内容组织和连续操作体验 |
| 本地存储异常处理和现有领域测试 | 显示名称、可选择载入的示例数据与重置确认 |
| 已验证的 GitHub Pages 发布方式 | 独立预览、画面对照和发布后的实际操作验证 |

Ant Design 继续用于适合的表单、弹窗、抽屉、提示等组件。页面布局、导航和业务内容的视觉由原型决定；具体控件根据画面和交互适配。

HTML 原型使用原生 JavaScript 拼接页面和委托事件。React 版本需要将页面拆成组件，用状态和事件处理维护相同的可见行为。

## 推进顺序

1. 固定原型和当前线上版的版本，整理四个页面、弹窗、助手各阶段的参考截图与操作路径。
2. 迁移原型外壳和首页，先确认桌面布局、内容比例、日夜主题和主要入口。
3. 迁移日历、项目、设置和快速添加，接入已有的保存、编辑、删除和项目管理。
4. 迁移助手输入、草案核对、确认反馈的完整交互，保持用户确认后才写入安排。
5. 对照原型检查画面，验证操作、刷新持久化与窄屏布局，再发布供试用。

新版使用独立预览地址，保留当前线上版用于比较。试用后再决定默认入口，避免比较过程中发生版本混淆。

- 原型布局预览：<https://gthezi.github.io/will-demo/prototype/>
- 原 React 版：<https://gthezi.github.io/will-demo/>

发布与验证步骤见 [预览版发布说明](prototype-preview-release.md)。

## 比较时需要控制的差异

原型默认有 5 项示例待办和 2 项示例日程，React 工程首次进入为空状态。这会影响对首屏内容和布局的评价。

新版提供明确标注的示例数据体验，同时保留真实空状态。点击“载入示例数据”并确认后，载入相对当前日期生成的 5 项待办和 2 项日程。载入会替换预览版当前的安排与项目；设置中的“清空安排”只清空安排，保留项目、名称和主题。两项操作均需确认。

现有 React 版本的自定义项目、归档和存储错误处理继续可用。新预览版使用 `will-prototype-schedule-v01`，首次无该键时读取同源旧版的 `will-react-schedule-v01`，后续只写入预览版键，不覆盖旧版安排。显示名称单独保存，主题偏好沿用 React 版共享键。HTML 原型的数据不自动导入。

验收应同时覆盖有数据、空状态、长标题和较多事项，避免只检查示例画面。

## 暂缓的产品问题

用户要求先记住以下讨论，留待后续处理：

- 当前日程与待办的区分、完成入口和筛选关系容易让人困惑。
- 已提出的候选方向是统一以“安排”呈现，区分固定时段与截止期限，并重新设计完成状态的适用范围。
- 首页的近期摘要与全部安排应有清楚的范围区分。
- 添加安排时可考虑就地新建关联项目，创建后自动选中并保留已填内容。

“统一安排和完成状态”目前是留待设计确认的方向，尚未成为已经实现或确定的数据规则。本轮原型工程化优先恢复布局与交互体验，后续集中处理这些语义和数据模型变化。

## 试用范围
